# 供应商与模型设置改版提案

> 状态：设计草稿，待 Dash 审阅；不是已批准的产品规则或已实现功能。
> 日期：2026-10-29。范围：Desktop 设置与任务侧栏；同时定义窄屏和远程使用边界。
> 评审修订版：沿用上下文即时保存，使用连接批量编辑，明确选中态涉及现行规则变更。
> 本 PR 提交设计方案与[交互式 HTML 预览](./provider-settings-preview.html)，不修改应用运行时代码、凭证或默认模型资料。

判断标准：新用户不懂引擎也能接通；老用户换 Key 不必改三遍；高级用户找得到例外；
已有配置不悄悄改变。原始反馈缺失部分仍按证据边界处理，不因预览可操作而宣称功能已完成。

推荐：柔和的任务选中底；上下文在失焦/Enter 时保存；换 Key 一次填写、保存到明确列出的引擎；
添加模型默认选择已配置且确实支持该型号的接入位置。无需为了这些改善建立永久继承或迁移旧配置。
其中选中底有意改变现行 DESIGN §15.10 的反色规则，仍是待审阅的设计建议；本 PR 不改权威规则。

反馈来自 Dash 转来的用户讨论。原帖图片短链无法读取，以下将文字反馈与源码核实分开。
其中「明明是上下文有 1M」和最后的「2」缺少后文，不能补写成已确认的问题。

## 2. 信息架构：连接、模型、模型设置分开

保留现有供应商详情页，不新建一个与现有模型列表竞争的全局模型页面。
顶部沿用统一身份、真实连接状态、一个主要操作与更多菜单；编辑连接仍从更多菜单进入。
模型列表工具行增加「添加模型」，不把它挤进供应商身份行。

**首次接入与日后维护分开。** 首次保留「选择来源 → 连接 → 选择模型 → 完成」引导，
连接保存后直接进入选模型，不把用户留在空列表。允许明确选择稍后添加时，完成页说明
「连接已配置，还没有可用模型」并提供添加入口，不能显示为已准备就绪。
日后换地址/Key 只编辑连接；增加型号只打开模型列表旁的添加弹窗。

```text
供应商详情
  品牌 · 连接名称 · 接入类型        状态  [主要操作] [⋯]
  账号 / 服务地址
  用量（实际提供时显示）

  模型                  [搜索] [筛选] [添加模型]
  模型 A    上下文摘要    显示开关    [详情]
  模型 B    上下文摘要    显示开关    [详情]

  ⋯ → 编辑连接设置 → 只修改连接
  添加模型         → 默认显示目录；找不到时手动添加
  模型详情         → 模型资料、使用上限、高级设置
```

「添加模型」只对具备实际写入能力的用户 API 连接显示。订阅来源不能借此伪造账号成员；
本机模型继续使用已有安装/管理流程。远程或分享来源复用执行端的真实可写能力，
不在本机新建同名连接，也不显示会失败的假保存按钮。
保留已有语音参考型号规则、默认勾选和权限限制，将专用入口复用进同一添加流程，
不把订阅自动转换为 API 连接。

## 3. 连接编辑：一次填写，明确一起修改谁

默认可见内容控制在名称、URL、凭证和两个折叠行。不要求用户理解「公共值」「继承」或
「覆盖」。展示本次编辑的分组及例外，保存时分别更新各引擎原有配置。下图均为占位数据。

```text
编辑连接设置

名称          [我的供应商                       ]
服务地址      [服务地址                         ]
API key       已保存                  [更换]
              Claude Code、Codex、Pi 当前使用相同 Key

▸ 不同引擎使用不同连接
  Codex 使用单独地址
▸ 高级连接设置                         已配置请求路径

更换 Key 后显示：将更新 Claude Code、Codex、Pi 使用的 Key
                                     [取消] [保存]
```

展开后每个引擎先显示本次使用哪份值；提供「单独修改地址」「单独修改 API key」
开关，只展开启用项的输入。URL 与 Key 分别分组，例如 Codex 使用专属路径但可以一起换 Key。
收起摘要点名例外，如「Codex 使用单独地址」，没有例外时显示「都使用上面的连接」。
不要用「2 项继承、1 项覆盖」代替实际影响。更换地址或 Key 后显示针对本次修改的影响摘要，
未修改时不常驻一块影响说明。
显示脱敏后的有效地址及凭证来源，不回显秘密用于比较，不把「已配置」当成「已验证」。
本次编辑仅属于当前连接 ID；同品牌的另一个账号不受影响。

### 分组和保存边界

- 打开时只读实际配置。地址必须比较完整接入地址，不能把同 origin 的不同路径合成同一个 URL；协议、请求路径、目录地址和请求头继续保留各自边界。
- Key 是否相同、能否一起修改由 Main 在既有凭证作用域内判断，只向界面提供分组和脱敏来源；不能把遮罩相同当成秘密相同，不能为分组回传秘密。现有 `customProviderRuntimeFill` 是 renderer 草稿比较，不是已实现的 Main 分组能力。
- 相同 Key、同 origin 只是候选条件；端点绑定、隐藏请求头及现有兼容判据同样必须通过。不能确认时保持单独编辑，不自动扩大使用范围。
- 临时分组在字段旁点名，变更后显示受影响引擎。用户可排除某一引擎；保存是对该次批量修改的提交，不持久化任何继承关系。
- 不同旧值默认保持独立。主动选择一起修改时，选来源、看差异后保存；不要求重新输入原 Key，也不为普通同范围更换增加第二次确认。
- 新建连接只在已识别、已支持、已选择的接入范围内填入；不因填了 URL 就启用全部引擎或兼容模式。地址相同不意味着协议相同，不硬拼 `/v1` 等后缀。
- URL 变化沿用现有端点与凭证绑定规则。同源也不能跳过规则；跨 origin 未明确选择该目标可用的凭证前，不发出带 Key 的目录探测或测试。
- 取消编辑没有写入；保存只更新所编辑字段，不能用旧模型列表快照覆盖期间新增的型号。
- 保存时通过既有配置更新入口复核最新端点、凭证和目标；有冲突就保留草稿、显示差异。若发生部分成功，明确哪些已更新、哪些未更新，不显示笼统成功。
- 保存前自动展开并定位隐藏区的错误。保存失败保留输入，说明失败字段与实际原因；不默认提示重试。
- 关闭折叠不清空字段；有例外显示摘要。将某项重新纳入一起修改，表示本次写入同一个值，不承诺未来自动同步。

### 高级设置的显隐原则

低频不是隐藏当前问题的理由。默认收起完整参数；已有自定义显示具体摘要；当前错误及其
恢复入口必须常显。隐藏字段阻止保存时，先显示原因，提交时展开定位首个错误，不能只留下
一个灰色保存按钮。协议错误只在宿主已确认时说明，不通过预览或前端猜测。

**存量配置始终独立保存，不增加持久继承。** 重新打开按当时的真实值重新分组，旧客户端
仍读取原格式。现有同步填入的冲突及端点兼容判据可以复用，但不能把“相同”直接等同于
“可安全复制”。远控执行端不能提供可信分组或批量更新时，保留原有单独编辑能力。
此方案不需要凭证迁移；不新增存储 schema，也不以草稿批准任何协议变更。

### 高级字段去向

| 内容 | 新位置 | 默认表现 |
| --- | --- | --- |
| URL、Key | 连接基础字段 | 常显 |
| 各引擎不同的地址、凭证来源 | 不同引擎使用不同连接 | 折叠并点名例外 |
| 协议、请求路径、目录地址、自定义请求头 | 高级连接设置，内部按对应引擎组织 | 折叠；仍保留每项已有支持限制 |
| 型号 ID、名称、类型 | 添加模型弹窗 / 模型详情 | 不在连接编辑页出现 |
| 上下文使用上限 | 模型详情 | 常显摘要与「调整」；点击后编辑 |
| 自动压缩、接口选择、能力和价格覆盖 | 模型详情的高级设置 | 折叠并标记自定义项；报价本身仍正常展示 |
| 鉴权失败、地址无效、保存失败 | 对应字段及页内错误说明 | 始终可见，不藏进折叠摘要或 tooltip |

## 4. 添加模型：把大块编辑器变成主动操作

```text
添加模型 · 我的供应商
  [搜索模型                              ]
  □ 模型 C                               对话
  □ 模型 D                               语音合成
  ✓ 模型 A                               已添加

  找不到型号？ [手动添加型号]

                                     [取消] [添加]
```

- 不先给两个等权页签让用户选流程。目录是默认主路径，手动入口固定在目录外，搜索无结果也可达。
- 手动页默认只显示型号 ID（必填）、显示名称（可选），并可返回目录；仅在自动判断不足且影响实际接入时才要求补类型或接入位置，不常驻一套完整模型表单。
- 对已确认支持的型号，默认加入本连接下已配置且有权限使用的兼容引擎，显示「将在 Claude Code、Codex 中可用」等准确摘要；改选放在高级区域。多个型号支持范围不同时逐项说明，不虚构共同范围。
- 目录不可用或为空时保留手动添加，不把目录读取失败说成连接一定失效。
- 相同连接/引擎/型号重复提交不重复添加；多个引擎拥有同一型号仍由统一模型行聚合，不跨账号去重。
- 只追加选择的新型号，保留现有隐藏开关、名称覆盖、协议、能力和排序。已有同名 ID 不静默覆盖。
- 资料优先沿用目录，不要求用户先填写上下文、价格和推理参数；新增型号不等于调用已验证。
- 未知型号不能推断支持范围时，在当前步骤直接说明并要求补齐；不把阻断项藏在高级区域，不自动启用新引擎或兼容模式。语音等直接调用型号沿用专用入口，不伪装为三引擎通用型号。
- 添加成功关闭弹窗并定位新行；失败保留选择。搜索不取消已选项，跨页保留草稿；取消/Esc 放弃本次草稿，再次打开回到目录。打开、取消、切换页面不写配置。
- 新增供应商保留「选择来源 → 连接 → 选择模型」流程，复用同一模型编辑器，不把复杂内容重新塞回连接步骤。

## 5. 上下文：能直接输入，也能解释为什么不是 1M

模型详情先给摘要和「调整」入口，不默认铺开输入框。下面为说明布局的假设数值，不是任何型号的规格声明：

```text
上下文
使用上限           自动 · 200,000 tokens        [调整]
模型最大容量       1,050,000 tokens

点击「调整」后：
快捷选择 · tokens
[✓ 跟随默认 · 200,000] [262,144] [1,000,000] [接入上限 · 1,050,000]
点击即保存；固定额度与跟随默认是不同操作。

或输入自定义上限   [ 200000                     ]
                   = 200,000 tokens
                   支持 1M、100万或 1000000
输入 1M 后：
                   = 1,000,000 tokens
失焦或按 Enter 保存；Esc 放弃尚未保存的输入。
已保存
提高数值不会扩展模型能力；实际生效还受当前任务和引擎限制。
                    [完成]

▸ 高级设置                             已自定义 1 项
  自动压缩 · 接口选择 · 其他模型覆盖
```

数据层仍明确区分供应商容量、默认预算与用户覆盖，但不把三层概念同时铺在首屏。
「自动」表示跟随当前默认，默认变化仍会生效；自定义后摘要显示「自定义 · 精确值」。
默认较小时说明这是当前默认使用上限，不暗示供应商只有该容量，也不能未经依据承诺更快或更便宜。
资料未知时写未知，不从型号名猜容量。
仅在当前路由明确支持且现有校验允许时，提供「使用当前接入上限（精确值）」快捷操作；
按用户覆盖保存，不暗示一直跟随未来容量。上限未知或原生运行窗口不明确时不显示。
原帖「明明是上下文有 1M」被截断，不能据此认定用户一定在要求用满，更不能将标称容量直接作为安全预设。
实际运行任务如还有原生预留或任务窗口限制，在现有任务窗口入口展示最终值与限制来源，
不把设置页保存值冒充正在运行的实际容量。自动压缩沿用当前按连接/模型的规则，不改默认比例。

### 快捷选择与精确输入

采用少量快捷选项加输入框，不提供滑杆。上下文范围跨度大、需要保留精确整数，滑杆步长
难以兼顾；用户也很难知道拖到哪个数值合理。快捷项集中在「调整」区域，未展开时只显示摘要。

- 「跟随默认」同时显示当前精确额度；点击即清除用户覆盖，继续跟随后续默认变化。
- 固定预设优先沿用该模型/引擎已有且允许的额度，数量保持少量。图中 262,144 演示旧预设
  的精确保留，1,000,000 演示另一档固定额度；两者不是所有型号通用的推荐值。
- 「接入上限」仅在前述能力条件成立时出现，显示精确额度；点击保存当下数值，不自动追随
  后续容量变化。固定预设与接入上限数值相同时只保留一个；跟随默认保留独立语义。
- 所有快捷项都即时保存，与手输提交后的结果一致。成功后同步输入框、摘要和选中标记；
  点击快捷项直接替换当前草稿，不先保存草稿再保存预设。失败保留之前已保存的选择。
- 已保存的设置与某个选项一致时显示勾选、描边与 `aria-pressed`。输入未提交时清除快捷项
  高亮，摘要仍保留已保存值；手输精确匹配预设并保存后恢复对应选中态。固定值即使等于
  默认额度，也不能标为「跟随默认」。
- 输入框始终允许按现有规则填写其他精确值；`1M`、`100万` 只在提示中说明等价写法，
  不做成两个重复选项，也不出现「试填」等测试操作。

### 输入合同

| 输入 | 解析结果 |
| --- | --- |
| `1000000`、`1,000,000` | 1,000,000 tokens |
| `1M`、`1m`、`1.5M` | 1,000,000 / 1,500,000 tokens |
| `128K`、`128k`、`1.5K` | 128,000 / 1,500 tokens |
| `100万` | 1,000,000 tokens |
| `1048576` | 1,048,576 tokens，原样保留 |

K = 1000，M = 1,000,000，万 = 10,000。裸数按 tokens；允许首尾空白与数值/单位间空格。
千分位仅接受完整三位分组；小数点统一为 `.`；不将逗号当小数点，也不盲删非法字符。
拒绝负数、零、非有限值、科学计数法、未知单位、不规范分组和换算后非安全整数，显示就地错误。
解析合法与业务范围合法分两步：继续使用当前模型/引擎允许范围，不因支持 `1M` 就放宽上限，
也不凭目录容量新增硬限制。超出当前范围时显示准确范围；现有允许但有风险的覆盖保留原警示。

输入时显示精确换算，不抢光标、不边输入边改写文本。沿用当前抽屉的即时保存模型：
**有修改且有效时，失焦/Enter 提交；无修改不写入。** 不增加另一个保存按钮。
提交后显示「已保存」，失败保留原有效值和草稿，不提前更新摘要。清空或非法输入不清除覆盖，
保留草稿并就地说明；「完成」须先成功提交或恢复旧值。Esc 仅放弃尚未保存输入并关闭编辑，
焦点回「调整」，不能声称撤销此前已经保存的值。完成/关闭不另触发一次重复保存。
「跟随默认」即时删除用户覆盖并反馈结果，与抽屉其他恢复默认操作一致。
未编辑的旧精确值、旧低值不因打开/失焦而变化；`1,048,576` 不能截成 `1048K` 后再保存。
只有无损缩写才可作为回显输入，例如 1,000,000 → `1M`；其他值优先回显原整数。
所有预设共用精确值与格式化规则；保留现有 262144 token 能力，修正「256K」标签歧义，
不把格式统一变成额度调整。原型用「262,144」与该组的 tokens 单位演示该预设的即时保存。
详情提供精确数字，窄列表可以用约数；两者共用同一格式化规则。

## 6. 任务选中态：减少大面积反色，保持可识别

保留任务行现有形状与布局，不新增装饰边条或动画。选中态由中性填充、现有标题字重与
必要的内描边共同表达；文字使用与选中底配对的前景 token。

这是**有意修订 DESIGN §15.10 已登记规则**，不是修复偏离规范的单页样式。当前 Light
为 `#3C3F43 / #FCFCFC`、Dark 为 `#EEEEEE / #151515`，与中性主按钮同组。
推荐在 CINDY Light/Dark 改为同一墨色的低 alpha 填充：hover 约 5%，selected 约 10–12%
作为试验起点，选中前景 token 指向 primary，保留 600 字重。具体值仍需按实际底色验证。
Dash 确认方向后，实施须在同一改动中更新 §15.10、token 正本及锁定旧值的设计判据。
本草稿保留现行权威规范，预览不能作为已获批准的替代规则。

| 状态 | Light | Dark |
| --- | --- | --- |
| 普通 | 既有侧栏背景、普通文字 | 既有侧栏背景、普通文字 |
| 悬停 | 轻微中性填充 | 轻微中性提亮 |
| 选中 | 稍深于悬停，深色文字 | 稍亮于悬停，浅色文字；避免近白底 |
| 键盘焦点 | 独立焦点环，可与选中共存 | 同样独立，不以亮底代替焦点环 |

实现从设计 token 正本成对调整 `sidebar-item-active`、`sidebar-item-active-foreground`、
`sidebar-item-active-border`，不在 `SessionItem` 写主题判断补丁，不修改生成文件作为真相源。
先覆盖存在问题的 CINDY Light/Dark，检查共享 token 的任务、项目、伙伴、设备、自动任务行和其他消费者；
第三方主题保留自身语义，不为修一个主题把所有主题改成同一颜色。
检查副标题、日期、更多按钮、标签边缘、未读及运行状态，避免只有主标题可读。
普通文字对比度目标至少 4.5:1；选中与悬停需实际可分辨，不以 token 存在代替目检。
同时验证运行图标 `warning-accent`、按背景明度选择的 PR open 绿色与 Mobile 对应选中/状态 token。
必要状态图标与实际合成底色的对比度至少 3:1；不得用降低运行状态优先级来掩盖不足。
浅底可能使现有橙色不够清晰，最终值需连同透明背景一起实测，不能直接采用评审中的估算比值。
当前 HTML 只演示选中填充方向，未证明这些真实状态图标已通过。

## 7. 响应式与可访问性

- Desktop 弹窗沿用 `min(600px, 100vw - 32px)` 的家族宽度、容器滚动和固定操作区；不为了装下全部高级项放大为巨型表单。
- 320px 宽度时标签与输入纵向排列，按钮换行，长 URL/型号可换行或在字段内滚动，页面不得横向溢出；手机不要求悬停才能读到范围和错误。
- 使用现有 Button、FormField、输入、Disclosure/折叠与 Dialog 规范；单行输入/按钮为 pill，弹窗为 12px 容器，不新增圆角档位。
- 折叠按钮有可访问名称、`aria-expanded` 与键盘操作；错误与字段关联，提交时展开隐藏错误并聚焦首项。
- 弹窗关闭后焦点回原入口；有取消按钮不另加右上角 ×，点遮罩不关闭表单。未保存修改的退出沿用既有保护行为。
- 两种模式都设计 default、hover、focus、disabled、loading、empty、error；实机是否验过分别记录。
- Mobile 若尚无同等设置入口，不借方案宣称已经具备；后续远程编辑复用执行端解析与权限，混合版本需明示支持范围。

## 8. 实施顺序与验收

以下是方案内的建议顺序，不代表此 PR 已实现。按可独立验收的内容推进，暂不另建实现 PR。

1. **上下文输入与预设**：精确解析、262144 回显、即时保存与容量说明，沿用现有范围校验。
2. **任务选中态**：设计方向确认后，连同规则、token 和状态图标一起调整，产出真实 Light/Dark 对照；不阻塞第一项。
3. **连接与模型分层**：高级项折叠、模型增删移入列表弹窗、新建流程复用。保留语音和订阅来源边界。
4. **一次填写多处保存**：复用已有独立配置与冲突判断，核验凭证作用域、最新配置与失败反馈；无需先实现持久继承。

| 验收场景 | 必须得到的结果 |
| --- | --- |
| 新用户接入普通 API | 连接步骤只填必要信息，不需阅读三套完整表单 |
| 首次连接保存、稍后添加模型 | 引导继续选模型；没有模型时明确未就绪并给入口 |
| 收起例外或高级项 | 看得见具体自定义摘要；阻断错误及恢复入口不被藏住 |
| 同作用域三引擎换 Key | 只填一次，明确列出的目标更新；排除项不动 |
| Codex 专属 URL、其他地址相同 | 一起修改地址不覆盖 Codex；协议仍正确 |
| 独立 URL 指向新 origin | 用户处理凭证作用域前无任何带 Key 的探测 |
| 旧字段相同/不同、隐藏请求头、仅一份已配置 | 打开/取消不写；仅可信且兼容字段可分组；主动一起修改显示差异 |
| 目录失败、空目录、重复型号、语音型号 | 可手动添加；不重复、不抹掉旧覆盖、不破坏语音规则 |
| 目录搜索无结果、跨页选择、取消再打开 | 手动入口始终可达；搜索/切页保留草稿；取消丢弃未提交选择 |
| 编辑期间另一路新增模型 | 连接保存不丢新增型号；实际写入合并最新配置 |
| `1M` / `100万` / 精确整数 / 非法值 | 换算一致；非法值不保存；业务范围仍有效 |
| 旧 `1048576` 打开再退出 | 原值完全保留 |
| 点击原 256K 对应预设 | 标签与保存值均为 262,144 tokens，重新编辑不截成 262000 |
| 默认低于容量、资料未知、运行中改值 | 说明来源与生效边界，不虚构容量或在途值 |
| 输入后失焦/Enter、非法草稿、Esc、恢复自动 | 有效修改只保存一次；非法保留草稿；Esc 不回滚已保存值；恢复自动即时生效 |
| 添加多个型号、不同支持范围 | 默认覆盖各自已配置的兼容位置；未知范围明确询问，不启用未授权模式 |
| 键盘、窄窗口、长名称、五种语言 | 无溢出，错误可达，焦点可返回 |
| 两种模式的选中/悬停/状态图标 | 清晰但不过度抢眼；有真实截图证据 |
| 远程、分享只读、混合客户端版本 | 不越权、不泄密；不支持分组的执行端保留原有编辑能力 |

后续实现按生产入口补最小回归，优先合入现有 `ModelAdvancedDrawer.test.tsx`、
`CustomProviderDialogAccessibility.test.tsx`、`customProviderRuntimeFill.test.ts`、
`customProviderEndpointEdit.test.ts` 及宿主保存/凭证测试；不以源码字符串断言替代行为验证。
本设计 PR 检查文档合同、链接、HTML 语法和浏览器交互/布局；HTML 使用虚构数据与内存状态，
不发网络请求、不读取真实凭证、不代表应用 UI 实机或真实账号/端到端验证。
