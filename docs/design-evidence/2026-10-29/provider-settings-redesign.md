# 供应商与模型设置改版提案

> 状态：设计草稿，待 Dash 审阅；不是已批准的产品规则或已实现功能。
> 日期：2026-10-29。范围：Desktop 设置与任务侧栏；同时定义窄屏和远程使用边界。
> 第二版：降低默认界面的概念负担，区分首次接入与日后维护。
> 本 PR 提交设计方案与[交互式 HTML 预览](./provider-settings-preview.html)，不修改应用运行时代码、凭证或默认模型资料。

第二版的判断标准：新用户不懂引擎也能接通；老用户换 Key 不必改三遍；高级用户找得到例外；
已有配置不悄悄改变。原始反馈缺失部分仍按证据边界处理，不因预览可操作而宣称功能已完成。

## 1. 问题与证据

目标：普通用户只需接好服务、选好模型；有特殊接入需求的人仍能找到完整控制项。
反馈来自 Dash 转来的用户讨论。原帖图片短链无法读取，以下将文字反馈与源码核实分开。
其中「明明是上下文有 1M」和最后的「2」缺少后文，不能补写成已确认的问题。

| 反馈 | 当前源码核实 | 建议 |
| --- | --- | --- |
| 夜间选中任务过亮，日间过黑 | `SessionItem.tsx` 使用专属选中背景、前景和内描边；CINDY 主题存在高反差配对，实际反馈主题、版本尚未知 | 改为低对比中性选中底，保留清晰文字、字重和焦点；按主题核验 |
| 上下文固定 K、不支持自由单位 | `ModelAdvancedDrawer.tsx` 的 `editableContextK` 向下取整；输入只接受整数 K，乘以 1000 保存；不是二进制 1024 换算 | 支持精确 tokens、K、M、万；编辑和只读说明使用相同数值 |
| 1M 容量与设置不一致 | 详情同时存在 `contextWindow`、`contextWindowMax`、使用上限与压缩设置；不能仅凭片段断言目录错误 | 在同一处解释容量、默认使用上限和用户覆盖；有原生预留时另列实际可用值 |
| 各 Runtime 重复填写 URL、Key | 编辑态仍以 Runtime 分栏；已有同步填入、冲突预览和部分新增态同步逻辑 | 以连接公共值为主、各引擎例外为辅，避免用户维护三份公共字段 |

## 2. 信息架构：连接、模型、模型设置分开

保留现有供应商详情页，不新建一个与现有模型列表竞争的全局模型页面。
顶部沿用统一身份、真实连接状态、一个主要操作与更多菜单；编辑连接仍从更多菜单进入。
模型列表工具行增加「添加模型」，不把它挤进供应商身份行。

**首次接入与日后维护分开。** 首次保留「选择来源 → 连接 → 选择模型 → 完成」引导，
连接保存后直接进入选模型，不把用户留在空列表。允许明确选择稍后添加时，完成页说明
「连接已配置，还没有可用模型」并提供添加入口，不能显示为已准备就绪。
日后换地址/Key 只编辑连接；增加型号只打开模型列表旁的添加弹窗。

```text
供应商详情
  品牌 · 连接名称 · 接入类型        状态  [主要操作] [⋯]
  账号 / 服务地址
  用量（实际提供时显示）

  模型                  [搜索] [筛选] [添加模型]
  模型 A    上下文摘要    显示开关    [详情]
  模型 B    上下文摘要    显示开关    [详情]

  ⋯ → 编辑连接设置 → 只修改连接
  添加模型         → 默认显示目录；找不到时手动添加
  模型详情         → 模型资料、使用上限、高级设置
```

「添加模型」只对具备实际写入能力的用户 API 连接显示。订阅来源不能借此伪造账号成员；
本机模型继续使用已有安装/管理流程。远程或分享来源复用执行端的真实可写能力，
不在本机新建同名连接，也不显示会失败的假保存按钮。
保留已有语音参考型号规则、默认勾选和权限限制，将专用入口复用进同一添加流程，
不把订阅自动转换为 API 连接。

## 3. 连接编辑：一份公共连接，按需设置例外

默认可见内容控制在名称、URL、凭证和两个折叠行。外层不要求用户理解「公共值」「继承」或
「覆盖」；只有展开例外后才说明使用哪份地址和凭证。下图字段值均为占位，不含真实地址或密钥。

```text
编辑连接设置

名称          [我的供应商                       ]
服务地址      [服务地址                         ]
API key       已保存                  [更换]

▸ 不同引擎使用不同连接
  Codex 使用单独地址
▸ 高级连接设置                         已配置请求路径

更换 Key 后显示：将更新 Claude Code、Codex、Pi 使用的 Key
                                     [取消] [保存]
```

展开后每个引擎先显示「使用上面的连接」或具体例外；提供「使用单独地址」「使用单独 API key」
开关，只展开启用项的输入。URL 与 Key 独立，例如 Codex 使用专属路径但仍使用上面的 Key。
收起摘要点名例外，如「Codex 使用单独地址」，没有例外时显示「都使用上面的连接」。
不要用「2 项继承、1 项覆盖」代替实际影响。更换地址或 Key 后显示针对本次修改的影响摘要，
未修改时不常驻一块影响说明。
显示脱敏后的有效地址及凭证来源，不回显秘密用于比较，不把「已配置」当成「已验证」。
公共设置仅属于当前连接 ID；同品牌的另一个账号不受影响。

### 继承与兼容边界

- 新建连接在已识别且已支持的接入范围内复用公共字段；不因填了公共 URL 就启用所有引擎或兼容模式。
- 公共 URL 是用户输入的接入地址，不意味着三引擎共用相同协议。请求路径、协议和接口模板继续按现有路由解析，不硬拼 `/v1` 等后缀。
- 更新公共 Key 时，沿用公共 Key 的路由一起更新，独立 Key 保留；更换前显示影响范围，不增加普通同源更新的重复确认。
- 单独 URL 换成另一个 origin 时，不自动携带公共 Key 发出目录探测或测试。按现有凭证作用域规则，需明确选择该目标可用的凭证；认可跨域使用前不得发送。
- 取消编辑没有写入；保存只更新所编辑字段，不能用旧模型列表快照覆盖期间新增的型号。
- 保存前自动展开并定位隐藏区的错误。保存失败保留输入，说明失败字段与实际原因；不默认提示重试。
- 关闭折叠不清空字段；有覆盖显示摘要。恢复某字段的公共设置删除该字段的独立覆盖，不复制当时的公共值。

### 高级设置的显隐原则

低频不是隐藏当前问题的理由。默认收起完整参数；已有自定义显示具体摘要；当前错误及其
恢复入口必须常显。隐藏字段阻止保存时，先显示原因，提交时展开定位首个错误，不能只留下
一个灰色保存按钮。协议错误只在宿主已确认时说明，不通过预览或前端猜测。

**存量配置不按值相等猜测继承关系。** 旧三份配置继续视为独立配置，初次打开不写入、
不改地址、协议、模型与密钥。用户可主动选择「统一连接设置」，选来源、看差异和受影响引擎，
再保存；现有冲突预览可作为复用基础。旧配置不需要重新填写凭证，也不因未统一而无法使用。

公共值与字段覆盖需要在宿主配置层有明确来源，不能只在表单中复制三份后声称长期继承。
后续实现须设计版本化的非敏感引用及旧格式兼容投影，秘密仍在既有凭证库；未定义旧客户端
写回、混合版本远控和回滚策略前，不上线持久继承。此草稿不批准任何存储或协议变更。

### 高级字段去向

| 内容 | 新位置 | 默认表现 |
| --- | --- | --- |
| URL、Key | 连接基础字段 | 常显 |
| 各引擎不同的地址、凭证来源 | 不同引擎使用不同连接 | 折叠并点名例外 |
| 协议、请求路径、目录地址、自定义请求头 | 高级连接设置，内部按对应引擎组织 | 折叠；仍保留每项已有支持限制 |
| 型号 ID、名称、类型 | 添加模型弹窗 / 模型详情 | 不在连接编辑页出现 |
| 上下文使用上限 | 模型详情 | 常显摘要与「调整」；点击后编辑 |
| 自动压缩、接口选择、能力和价格覆盖 | 模型详情的高级设置 | 折叠并标记自定义项；报价本身仍正常展示 |
| 鉴权失败、地址无效、保存失败 | 对应字段及页内错误说明 | 始终可见，不藏进折叠摘要或 tooltip |

## 4. 添加模型：把大块编辑器变成主动操作

```text
添加模型 · 我的供应商
  [搜索模型                              ]
  □ 模型 C                               对话
  □ 模型 D                               语音合成
  ✓ 模型 A                               已添加

  找不到型号？ [手动添加型号]

                                     [取消] [添加]
```

- 不先给两个等权页签让用户选流程。目录是默认主路径，手动入口固定在目录外，搜索无结果也可达。
- 手动页默认只显示型号 ID（必填）、显示名称（可选），并可返回目录；仅在自动判断不足且影响实际接入时才要求补类型或接入位置，不常驻一套完整模型表单。
- 目录不可用或为空时保留手动添加，不把目录读取失败说成连接一定失效。
- 相同连接/引擎/型号重复提交不重复添加；多个引擎拥有同一型号仍由统一模型行聚合，不跨账号去重。
- 只追加选择的新型号，保留现有隐藏开关、名称覆盖、协议、能力和排序。已有同名 ID 不静默覆盖。
- 资料优先沿用目录，不要求用户先填写上下文、价格和推理参数；新增型号不等于调用已验证。
- 未知型号需选择实际可用接入位置时，在高级区域说明；不通过添加模型默许兼容模式授权。
- 添加成功关闭弹窗并定位新行；失败保留选择。搜索不取消已选项，跨页保留草稿；取消/Esc 放弃本次草稿，再次打开回到目录。打开、取消、切换页面不写配置。
- 新增供应商保留「选择来源 → 连接 → 选择模型」流程，复用同一模型编辑器，不把复杂内容重新塞回连接步骤。

## 5. 上下文：能直接输入，也能解释为什么不是 1M

模型详情先给摘要和「调整」入口，不默认铺开输入框。下面为说明布局的假设数值，不是任何型号的规格声明：

```text
上下文
使用上限           自动 · 200,000 tokens        [调整]
模型最大容量       1,050,000 tokens

点击「调整」后：
使用方式           [ 自动 / 自定义              ]
自定义上限         [ 1M                         ]
                   = 1,000,000 tokens
                   支持 1M、100万或 1000000
提高数值不会扩展模型能力；实际生效还受当前任务和引擎限制。
                            [取消] [保存]

▸ 高级设置                             已自定义 1 项
  自动压缩 · 接口选择 · 其他模型覆盖
```

数据层仍明确区分供应商容量、默认预算与用户覆盖，但不把三层概念同时铺在首屏。
「自动」表示跟随当前默认，默认变化仍会生效；自定义后摘要显示「自定义 · 精确值」。
默认较小时说明这是当前默认使用上限，不暗示供应商只有该容量，也不能未经依据承诺更快或更便宜。
资料未知时写未知，不从型号名猜容量。
实际运行任务如还有原生预留或任务窗口限制，在现有任务窗口入口展示最终值与限制来源，
不把设置页保存值冒充正在运行的实际容量。自动压缩沿用当前按连接/模型的规则，不改默认比例。

### 输入合同

| 输入 | 解析结果 |
| --- | --- |
| `1000000`、`1,000,000` | 1,000,000 tokens |
| `1M`、`1m`、`1.5M` | 1,000,000 / 1,500,000 tokens |
| `128K`、`128k`、`1.5K` | 128,000 / 1,500 tokens |
| `100万` | 1,000,000 tokens |
| `1048576` | 1,048,576 tokens，原样保留 |

K = 1000，M = 1,000,000，万 = 10,000。裸数按 tokens；允许首尾空白与数值/单位间空格。
千分位仅接受完整三位分组；小数点统一为 `.`；不将逗号当小数点，也不盲删非法字符。
拒绝负数、零、非有限值、科学计数法、未知单位、不规范分组和换算后非安全整数，显示就地错误。
解析合法与业务范围合法分两步：继续使用当前模型/引擎允许范围，不因支持 `1M` 就放宽上限，
也不凭目录容量新增硬限制。超出当前范围时显示准确范围；现有允许但有风险的覆盖保留原警示。

输入时显示精确换算，不抢光标、不边输入边改写文本。显式保存或 Enter 提交；Esc 取消编辑；
清空表示未完成输入；选择「自动」或「恢复自动」先改变编辑草稿，点击保存才删除覆盖。
取消或 Esc 保留原设置并回到摘要，焦点返回「调整」。保存失败保留草稿与原有效值。
未编辑的旧精确值、旧低值不因打开/失焦而变化；`1,048,576` 不能截成 `1048K` 后再保存。
只有无损缩写才可作为回显输入，例如 1,000,000 → `1M`；其他值优先回显原整数。
详情提供精确数字，窄列表可以用约数；两者共用同一格式化规则。

## 6. 任务选中态：减少大面积反色，保持可识别

保留任务行现有形状与布局，不新增装饰边条或动画。选中态由中性填充、现有标题字重与
必要的内描边共同表达；文字使用与选中底配对的前景 token。

| 状态 | Light | Dark |
| --- | --- | --- |
| 普通 | 既有侧栏背景、普通文字 | 既有侧栏背景、普通文字 |
| 悬停 | 轻微中性填充 | 轻微中性提亮 |
| 选中 | 稍深于悬停，深色文字 | 稍亮于悬停，浅色文字；避免近白底 |
| 键盘焦点 | 独立焦点环，可与选中共存 | 同样独立，不以亮底代替焦点环 |

实现从设计 token 正本成对调整 `sidebar-item-active`、`sidebar-item-active-foreground`、
`sidebar-item-active-border`，不在 `SessionItem` 写主题判断补丁，不修改生成文件作为真相源。
先覆盖存在问题的 CINDY Light/Dark，检查共享 token 的项目行、自动任务行和其他消费者；
第三方主题保留自身语义，不为修一个主题把所有主题改成同一颜色。
检查副标题、日期、更多按钮、标签边缘、未读及运行状态，避免只有主标题可读。
普通文字对比度目标至少 4.5:1；选中与悬停需实际可分辨，不以 token 存在代替目检。

## 7. 响应式与可访问性

- Desktop 弹窗沿用 `min(600px, 100vw - 32px)` 的家族宽度、容器滚动和固定操作区；不为了装下全部高级项放大为巨型表单。
- 320px 宽度时标签与输入纵向排列，按钮换行，长 URL/型号可换行或在字段内滚动，页面不得横向溢出；手机不要求悬停才能读到范围和错误。
- 使用现有 Button、FormField、输入、Disclosure/折叠与 Dialog 规范；单行输入/按钮为 pill，弹窗为 12px 容器，不新增圆角档位。
- 折叠按钮有可访问名称、`aria-expanded` 与键盘操作；错误与字段关联，提交时展开隐藏错误并聚焦首项。
- 弹窗关闭后焦点回原入口；有取消按钮不另加右上角 ×，点遮罩不关闭表单。未保存修改的退出沿用既有保护行为。
- 两种模式都设计 default、hover、focus、disabled、loading、empty、error；实机是否验过分别记录。
- Mobile 若尚无同等设置入口，不借方案宣称已经具备；后续远程编辑复用执行端解析与权限，混合版本需明示支持范围。

## 8. 实施顺序与验收

以下是方案内的建议顺序，不代表此 PR 已实现或已授权存储迁移。

1. **先处理直接体验问题**：任务选中态配色；上下文精确输入与容量解释；连接高级项分组折叠。产出真实 Light/Dark 对照。
2. **再调整操作归属**：已有连接的模型增删移入列表弹窗；新建流程复用。保留语音和订阅来源的已有边界。
3. **最后交付公共连接继承**：完成宿主来源记录、旧配置主动统一、凭证作用域和旧端兼容；前两步不依赖先迁移凭证。
